# 冰务交接演练来源

场边测量网关、冰务班台账与裁判席交接记录采用本地合成资料。场边网关使用分轮缓冲协议，台账和裁判席按到达顺序公布记录。

使用 Node.js 22.23.4。运行 `npm test` 可检查资料分页、网关额度、原件摘要和阶段切换。运行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，环境变量 `PORT` 可调整端口。根路径返回当前回放阶段及台账来源名称。控制员可以用 `POST /control?stage=2` 切换到第二阶段。同一服务进程内，切换阶段不重置已用额度。

## 网关与读数

`GET /gateway/catalog` 返回轮次 `round`、网关时窗 `open` 和 `close`、当前剩余额度 `remaining` 以及本轮块目录 `blocks`。目录列出块标识、架号、首末序号、读取成本、最后一轮可取的轮次 `expires` 和 SHA-256。目录查询不收费，所列块是当轮可取的全部原件，后续轮次可能从中继架补出原目录未列出的块。可取块的内容和摘要由块标识唯一确定。

`GET /gateway/blocks/{id}` 返回 JSON 数组原件，摘要以 HTTP 响应原始字节计算。读取仍可取的块会从该轮额度扣除 `cost` 后发送响应，读到摘要不符的内容也已经扣费。额度不足返回 429，超过最后可取轮次返回 410，其余本轮不存在的块返回 404。这三个状态均不扣费。轮次只向前推进时，各轮的额度独立。此演练的五轮时窗按赛场时钟给出，回放不会等待现实时间流逝。

读数由架号和架内递增序号标识。同一架和序号可能有多个来源原件。每条读数还包括校验编号、架内探头名、摄氏温度和设备端的 `HH:MM` 时刻。同日内的时刻只精确到分钟。原件中的读数顺序、时间和温度都是设备提供的记录。

## 台账与裁判席

下列 GET 路由接受从零开始的 `offset` 和取值 1 到 100 的 `limit`，默认一页 3 条。记录有唯一来源键 `record`、首次可见轮次 `availableFrom`、类别 `kind` 与业务字段 `payload`。响应提供当前阶段 `stage` 和下一页偏移 `next`，到末页时 `next` 为 `null`。后续轮次保留既有记录，按首次到达顺序排列。

| 路由 | 来源记录 |
| --- | --- |
| `/source/probe` | `clock` 的 `deviceRange` 是设备时间的左闭右开区间，`shiftMinutes` 是加到设备时刻上的两个误差端点，端点均可取。带 `supersedes` 的回执只在自身设备时间区间内替换所指旧回执。`buffer` 提供架上仍能恢复的连续序号边界，端点均包含。`resolution` 指出指定架和序号最终采用哪份原件的读数。 |
| `/source/ice` | `layout` 给出架号、校验编号、探头所在冰格和左闭右开的赛场有效时间。`work.region` 列出施工实际影响的物理格，`begins` 到 `done` 的施工区间不含完工时刻。`crewWindow` 给出单次出勤允许进入的格、左闭右开的时窗和整趟容量，每格测量占一格容量。`job` 是班组对指定出勤窗口和格的回执，`accepted` 开始占用，`cancelRequested` 表示已收取消请求，`released` 表示该单已释放。 |
| `/source/referee` | `rule` 列出各赛道交接截止时间、所需物理格和含两端在内的温度范围。跨赛道的共用物理格使用同一标识。`handoff` 是裁判已收的交接凭据，列出已见范围、时间和支持凭据的来源读数。 |
